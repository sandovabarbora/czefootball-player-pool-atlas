### `src/config.py`
- `NATION` (env var, default `"cze"`), `nation()` (loads
  `config/nations/<NATION>.yaml`, raises `FileNotFoundError` with a clear
  message if missing), `HOME = nation()["code"]`, `squads() =
  nation()["squads"]`.
- `PROCESSED_DIR`, `OUTPUTS_DIR`, `SNAPSHOT_DIR` all nation-scoped.
- `DOMESTIC_LEAGUE = nation()["domestic_league"]`, `PEER_COUNTRIES =
  nation()["cohort_countries"]`.
- New `peers_meta()`: `countries.yaml`'s peer metadata restricted to and
  ordered by `PEER_COUNTRIES`. Needed because `countries.yaml::peers` is now
  one shared registry across nations (17 entries) — three call sites
  (`render.load_data`, `international_benchmark.main`, `big5_series.main`)
  used to read `countries()["peers"]` directly as "the peers to benchmark
  against"; left unguarded, England's peers would have leaked into a `cze`
  run's per-capita/cohort/Big-5 numbers the moment `countries.yaml` grew.
  All three now go through `peers_meta()`.

## Concerns / judgment calls (all explained in code comments, flagging here for visibility)
1. **`config.PEER_COUNTRIES` source**: the brief's `cohort_countries` example
   in `cze.yaml` is commented "today's COHORT_COUNTRIES order" but its 9
   values exactly match `config.PEER_COUNTRIES`'s order (from
   `countries.yaml`), not `render.py`'s actual 5-element `COHORT_COUNTRIES`
   list — I read this as the brief's own documentation slip (conflating two
   similarly-named things) and resolved it by wiring `config.PEER_COUNTRIES`
   from `cohort_countries` (verified empirically via the golden test, which
   depends on this being right) and giving `render.COHORT_COUNTRIES` its own
   new field, `cohort_exhibit`, not named in the brief's sketch but consistent
   with its "values = what the code hardcodes today" principle.
2. **`countries.yaml` becoming a shared registry**: adding England's peers
   directly into the existing flat `peers:` dict (as the brief specifies)
   would have leaked England's peers into a `cze` run's per-capita/cohort/
   Big-5 computations, since three call sites read `countries()["peers"]`
   verbatim. Added `config.peers_meta()` to fix this; verified via the
   golden test and a fresh `international_benchmark` run (still exactly the
   9 configured peers).
3. Chose not to touch `fetch_uefa_coefficients.py`'s `ASSOCIATION_TO_CODE`
   dict (has a `"Czech Republic"/"Czechia" → "CZE"` pair) — it's a general,
   nation-independent Wikipedia-name → FBref-code table already covering
   England, not a home-nation literal.
4. `data/raw/` and `site/img` (in `fetch_photos.py`'s `IMG_DIR`) were kept
   un-scoped by nation per the brief ("docs/img/players/ shared, fbref ids
   are global"); only `fetch_photos.py`'s Wikidata batch-cache dir became
   nation-scoped.

No `NEEDS_CONTEXT` was needed — both ambiguities above were resolvable
either by the brief's own stated principle or by empirical verification
against the golden fixture.
